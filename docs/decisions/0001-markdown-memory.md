# Markdown и Ontoship для памяти

## Контекст

Шаблон должен запускаться локально и сохранять знания между сессиями разных агентов.
Пользователь выбрал Ontoship и Ponytail, а также предложил подход LLM Wiki.

## Решение

Храним проверенные заметки в `docs/`, исходные материалы — отдельно в локальной папке `sources/`.
Используем закреплённый Python CLI Ontoship без изменений исходника.
Тонкий вход `scripts/kb.py` выбирает только документы из `docs/` и обновляет индекс перед поиском.
У каждого раздела есть README; значимые знания связаны ссылками и отмечены датой проверки.

## Причина

Файлы можно читать без поиска и переносить между инструментами. Git сохраняет историю.
SQLite FTS5 уже даёт локальный поиск. Для начального размера памяти отдельная служба не нужна.
Готовый HTML-граф Ontoship показывает связи без разработки отдельного интерфейса.

## Последствия

Агент должен обновлять знания после значимых изменений. Это рабочее правило, а не фоновая синхронизация.
Полная переиндексация перед запросом стоит времени на чтение всех заметок.
Структурные проверки не доказывают корректность содержания.
Сырой материал не попадёт в индекс сам, но агент может перенести его сведения в заметку: публикацию нужно проверять.

## Когда пересмотреть

Если измерения покажут медленный поиск, сначала оценить частоту и объём переиндексации.
Если возникают повторяющиеся ошибки поиска, собрать примеры запросов и только затем выбирать другой поиск.
Для обновления зависимости использовать процедуру из `vendor/ontoship/UPSTREAM.json` и корневых notices.
