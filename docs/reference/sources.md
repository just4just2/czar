# Источники и границы проверки

## Ontoship

Источник: [vakovalskii/ontoship](https://github.com/vakovalskii/ontoship).
Проверено 2026-10-03 по исходникам commit `3792acb40b4d631fb7b94b5fdc149e9a8ef2032d`.
CLI использует Python и SQLite FTS5. Индекс и HTML-карта создаются из Markdown.
Копия исходника, лицензия и контрольная сумма находятся в `vendor/ontoship/`.
Czar использует CLI; полный upstream dev-flow с обязательными стадиями выпуска не импортируется.

## LLM Wiki

Источник: текст «LLM Wiki», предоставленный пользователем 2026-10-03.
Авторство и публичный URL в материале не установлены. Исходный файл не включён в репозиторий.
Заимствована идея: отдельно хранить исходные материалы и накопленные выводы, связывать заметки и сохранять историю изменений.
Это описание подхода, а не доказательство качества конкретной системы памяти.

## Пост о понятных результатах LLM

Источник: [ссылка пользователя на пост Андрея Карпатого](https://x.com/karpathy/status/2105819303471976479).
Содержание изучено по цитате, предоставленной пользователем 2026-10-03; прямая загрузка X вернула HTTP 403.
Не подтверждаем дату публикации и точность атрибуции независимо от цитаты.
Принята идея выбирать подходящую форму объяснения: текст, схему, интерактивный HTML или отдельное видео.
Исходный пост целиком не воспроизводится.

## ASD-STE100

Официальный источник: [ASD-STE100](https://www.asd-ste100.org/),
[Issue 9, 2025-01-15](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf).
Проверено 2026-10-03 по доступным поисковым выдержкам официальной спецификации.
Полный PDF напрямую не загрузился (HTTP 403); полный словарь не проверен.
Пользователь также приложил обзорную схему. Это вспомогательный материал, а не нормативный источник.
Файлы стандарта и изображения не распространяются с шаблоном.
Навык содержит собственные инструкции и примеры адаптации; он не является сертифицированным средством проверки STE.

## Ponytail

Источник: локальный навык Ponytail, явно предоставленный пользователем; его метаданные указывают MIT.
Czar содержит собственную компактную адаптацию принципов, а не копию полного файла.
Приоритет: сначала понять задачу, затем использовать самое простое достаточное решение и проверить результат.
